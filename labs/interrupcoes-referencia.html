A ideia: o hardware chama o programa

Cada periférico tem um indicador (…IF) que o hardware liga quando o evento acontece, esteja a interrupção habilitada ou não. Uma interrupção só ocorre quando três chaves estão fechadas ao mesmo tempo: o indicador, a habilitação da fonte (…IE) e a habilitação global.

interrompe = …IF · …IE · GIE    (e também PEIE, se a fonte for de PIR1 ou PIR2)

Quando as três estão fechadas, o processador termina a instrução em curso, guarda o endereço de retorno na pilha, zera GIE e salta para o vetor. A rotina de tratamento roda, e o retorno religa GIE.

Regra de ouro Um indicador guarda "aconteceu", e não "quantas vezes". Se o evento ocorrer três vezes antes de o tratamento zerar o indicador, o programa vê um só. Quem precisa contar eventos rápidos conta no hardware (um temporizador como contador) ou trata cada um antes do próximo.

Ao ligar a interrupção, zere o indicador antes de habilitar. Ele pode estar ligado desde o reset ou desde o bootloader, e a interrupção dispararia na hora, sem evento nenhum.

A rotina de tratamento: modelo do curso

Um único tratamento atende todas as fontes. Ele pergunta, fonte por fonte, quem pediu, e testa também a habilitação quando ela é ligada e desligada pelo programa (como TXIE).

volatile uint8_t  borda = 0;          // sinalizador: o tratamento liga, o laço consome
volatile uint16_t contagem = 0;       // 16 bits: a leitura no laço NÃO é atômica

void __interrupt() tratar(void)
{
    if (INTCONbits.INT0IF) {          // 1. quem pediu?
        INTCONbits.INT0IF = 0;        // 2. apaga o indicador
        contagem++;                   // 3. trabalho curto
        borda = 1;
    }
    if (INTCONbits.TMR0IF) {
        INTCONbits.TMR0IF = 0;
        TMR0H = (uint8_t)(PRECARGA >> 8);   // alto primeiro
        TMR0L = (uint8_t)(PRECARGA & 0xFF);
        /* ... */
    }
    if (PIE1bits.TXIE && PIR1bits.TXIF) {   // fonte que liga e desliga
        /* ... */
    }
}

/* Opção 1: seção crítica curta */
INTCONbits.INT0IE = 0;          // desliga só a fonte que escreve a variável
uint16_t c = contagem;
INTCONbits.INT0IE = 1;

/* Opção 2: lê duas vezes até concordar (R7) */
static uint16_t ler16(volatile uint16_t *p)
{
    uint16_t a, b;
    do { a = *p; b = *p; } while (a != b);
    return a;
}

volatile é necessário, mas não suficiente: ele obriga o compilador a ler a memória a cada acesso, mas não torna a leitura de dois bytes indivisível.

Repique: o botão mente sobre quantas vezes foi apertado

Um contato mecânico abre e fecha várias vezes antes de assentar. Cada transição é uma borda, e cada borda liga INT0IF. A duração típica é de centenas de microssegundos a alguns milissegundos, e muda de botão para botão e de toque para toque.

filtro por confirmação: aceita um novo nível depois de K amostras iguais a cada T
atraso de reação ≈ K · T     (R7: T = 5 ms, K = 3 → cerca de 15 ms)
