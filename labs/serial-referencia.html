A ideia: quem faz o quê

DS39632E, p. 243, §20.0

A EUSART é um periférico que produz o quadro serial sozinho. O programa entrega um byte em TXREG e segue em frente; o hardware o põe no pino RC6, um bit de cada vez, no ritmo do gerador de taxa, um temporizador interno com recarga automática. Na recepção, o caminho é o inverso: o hardware monta o byte que chega pelo RC7 e o deixa em RCREG.

O periférico não conhece a fila: só esvazia TXREG e avisa com TXIF. Quem tira o próximo byte da fila e o põe em TXREG é a rotina de interrupção.

O quadro e os tempos

Formato do curso, 8N1: 8 bits de dado, sem paridade, 1 bit de parada. Em repouso a linha fica em 1; o bit de partida (0) cria a borda de descida que o receptor usa como referência, e a partir dela ele conta o tempo com o próprio relógio, amostrando cada bit no meio.

10dado, bit menos significativo primeiro11

Conta resolvida: 9600 bit/s

bit      = 1 / 9600            = 104,2 µs
byte     = 10 bits · 104,2 µs  = 1,042 ms    (8 de dado + partida + parada)
vazão    = 9600 / 10           = 960 bytes/s
eficiência = 8 / 10            = 80 %       (os 2 bits a mais pagam a falta de relógio)

linha de telemetria "125300,398,400,1,17\r\n" = 21 bytes
         = 21 · 1,042 ms       ≈ 22 ms no fio
         uma por segundo       ≈ 2,2 % do enlace

Na linha TTL do pino, repouso é 5 V. Depois do conversor RS-232 do kit os níveis são invertidos e maiores (cerca de ±10 V): o 1 lógico é a tensão negativa. Meça no pino, não no conector.

O gerador de taxa é um temporizador

DS39632E, p. 247, §20.1 e Tabela 20-1

Um contador conta pulsos do oscilador de n até 0, recarrega n sozinho e recomeça. Cada volta completa é um passo do quadro. O programa não escreve a taxa: escreve n, e a taxa resulta dele. É o mesmo papel do PR2 no PWM, também com recarga automática, e por isso todos os bits saem com exatamente a mesma largura.

BRG16BRGHTaxaDivisor nFaixa de n
00FOSC / (64 · (n + 1))n = FOSC / (64 · taxa) − 10 … 255 (SPBRG)
01FOSC / (16 · (n + 1))n = FOSC / (16 · taxa) − 10 … 255 (SPBRG)
10FOSC / (16 · (n + 1))n = FOSC / (16 · taxa) − 10 … 65 535 (SPBRGH:SPBRG)
11FOSC / (4 · (n + 1))n = FOSC / (4 · taxa) − 10 … 65 535 (SPBRGH:SPBRG)

Atenção A fórmula usa FOSC (16 MHz), não FCY (4 MHz). O "+1" vem de o contador ir de n até 0: são n + 1 passos. E n só vale para o relógio com que foi calculado.

Conta resolvida: 9600 bit/s a 16 MHz (BRG16 = 1, BRGH = 1)

DS39632E, p. 247, Tabela 20-1

1. isolar n:      n = 16 000 000 / (4 · 9600) − 1 = 415,67
2. arredondar:    n = 416                    (o contador só aceita inteiros)
3. caber:         416 > 255  →  precisa do contador de 16 bits (BRG16 = 1)
4. dividir:       416 = 0x01A0  →  SPBRGH = 0x01 (alto), SPBRG = 0xA0 (baixo)
5. taxa real:     16 000 000 / (4 · 417) = 9592,3 bit/s
6. erro:          (9592,3 − 9600) / 9600 = −0,08 %

Qual erro é aceitável

O receptor amostra o bit de parada 9,5 bits depois da borda de partida. Se até lá o desvio acumulado passar de meio bit, a amostra cai no bit vizinho:

limite do enlace = 0,5 / 9,5 ≈ 5,3 %     (soma dos erros dos dois lados)
regra prática = cada lado abaixo de 2 %

As interrupções da EUSART

DS39632E, p. 253, §20.2.1; p. 104, Registrador 9-4 (TXIF, RCIF)

São duas fontes, uma por sentido. As duas são periféricas: além do bit da fonte, precisam de PEIE e GIE.

FonteIndicador (PIR1)Habilitação (PIE1)Prioridade (IPR1)Vai a 1 quandoVolta a 0 quando
TransmissãoTXIF (b4)TXIE (b4)TXIP (b4)TXREG fica livreo programa escreve em TXREG
RecepçãoRCIF (b5)RCIE (b5)RCIP (b5)há byte em RCREGo programa lê RCREG até esvaziar
 
INTCONbits.PEIE = 1;   /* b6: libera as fontes periféricas (PIR1/PIE1) */
INTCONbits.GIE  = 1;   /* b7: libera tudo                              */
/* sem IPEN (= 0, o padrão), as prioridades são ignoradas e tudo vai para 0x0008 */

Diferente do Timer0 TXIF e RCIF não se zeram com uma escrita. Eles são só leitura e refletem o estado do periférico: TXIF só cai quando TXREG recebe um byte, RCIF só cai quando RCREG é lido. Um tratamento que testa RCIF e não lê RCREG é chamado de novo, sem parar.

Por que TXIE liga e desliga

Com nada a enviar, TXREG está livre, e TXIF fica em 1 o tempo todo. Se TXIE continuasse ligado, a interrupção seria pedida sem parar e o programa principal nunca mais rodaria. Por isso:

QuemQuandoFazSignificado
main (uart_enfileirar)põe um byte na filaTXIE = 1"acorda, tem trabalho"
ISRencontra a fila vaziaTXIE = 0"dormi; me chame quando houver mais"

RCIE fica sempre ligado: RCIF só vai a 1 quando chega um byte de verdade.

A fila de transmissão

Um vetor em RAM com dois índices. Cada índice tem um único dono, e por isso a fila dispensa desligar interrupções: os dois têm um byte, e cada escrita é uma instrução só.

ÍndiceAponta paraQuem escreve
entraa posição onde o próximo byte será escritosó o main
saia posição de onde o próximo byte será lidosó a ISR

vazia: entra == sai
cheia: (entra + 1) % FILA == sai     (uma posição fica sempre livre: cabem FILA − 1 = 63 bytes)
avançar: i = (i + 1) % FILA     (depois do 63 volta ao 0: a fila é circular)

Passo a passo: printf("Oi\r\n")

Contas da fila

main enfileira um byte          ≈ dezenas de ciclos  (µs)
fio leva um byte                = 1,042 ms           (~4170 ciclos a 16 MHz)
fila de 64 → 63 bytes no fio    = 63 · 1,042 ms ≈ 66 ms de folga
vazão máxima sustentada         = 960 bytes/s        (acima disso a fila enche
                                                      e o main volta a esperar)

FILA potência de 2 faz o % FILA virar um AND barato. Aumentar a fila só adia o problema se o programa produz mais de 960 bytes/s: aí é enviar menos ou subir a taxa.

Recepção e seus erros

DS39632E, p. 256, §20.2.2

O receptor guarda até 2 bytes em RCREG (uma pequena fila em hardware), mais o que está sendo montado no registrador de deslocamento.

ErroCausaConsequênciaComo sair
OERR (estouro)3.º byte termina de chegar com os 2 lugares ocupadoso byte se perde e a recepção para: nada novo entra até o programa agirzerar e religar CREN
FERR (quadro)bit de parada lido como 0: taxa errada, ruído, linha em curtoo byte provavelmente está erradoler RCREG (o indicador acompanha o byte)

Conta: quanto tempo até o estouro

3 bytes · 1,042 ms = 3,1 ms   (a partir da fila vazia, bytes chegando colados)

atualizar o display (encontro 3)       ≈ 1,3 ms  → cabe, por pouco, se for no main
transmissão bloqueante de 21 bytes     ≈ 22 ms   → estoura, se a recepção for por consulta
escrever no display DENTRO da ISR      → atrasa a próxima leitura: estoura

Por isso a recepção é por interrupção e o tratamento é curto: ele só guarda o byte num buffer; quem interpreta a linha é o main.

Fim da mensagem

O tratamento junta os bytes em linha[] e marca linha_pronta ao chegar \r ou \n. Terminais mandam \r\n: sem cuidado, o \n fecha uma segunda linha, vazia, por cima da primeira. E um terminal configurado sem final de linha nunca fecha a mensagem: os bytes chegam, mas nada acontece.

Código completo, testado (9600 8N1, 16 MHz)

#define FILA 64
static volatile uint8_t fila[FILA];
static volatile uint8_t entra = 0;     /* só o main escreve */
static volatile uint8_t sai = 0;       /* só a ISR escreve  */

static volatile char    linha[24];
static volatile uint8_t n = 0;
static volatile uint8_t linha_pronta = 0;

void uart_iniciar(void)
{
    TRISCbits.TRISC6 = 0;              /* TX */
    TRISCbits.TRISC7 = 1;              /* RX */
    BAUDCONbits.BRG16 = 1;             /* divisor de 16 bits     */
    TXSTAbits.BRGH    = 1;             /* taxa = Fosc / (4(n+1)) */
    SPBRGH = 0x01;                     /* n = 416 = 0x01A0       */
    SPBRG  = 0xA0;
    TXSTAbits.SYNC = 0;                /* assíncrono */
    RCSTAbits.SPEN = 1;                /* RC6 e RC7 passam ao periférico */
    TXSTAbits.TXEN = 1;
    RCSTAbits.CREN = 1;
    PIE1bits.RCIE  = 1;                /* recepção por interrupção; TXIE fica 0 */
}

/* Só o main chama: com a fila cheia ela espera a ISR. */
void uart_enfileirar(uint8_t b)
{
    uint8_t prox = (uint8_t)((entra + 1u) % FILA);
    while (prox == sai) { }            /* fila cheia: raro */
    fila[entra] = b;
    entra = prox;                      /* só depois de o byte estar na fila */
    PIE1bits.TXIE = 1;                 /* acorda o transmissor */
}

void putch(char c) { uart_enfileirar((uint8_t)c); }   /* printf usa esta */

void __interrupt() isr(void)
{
    if (PIE1bits.TXIE && PIR1bits.TXIF) {
        if (entra == sai) {
            PIE1bits.TXIE = 0;         /* nada a enviar */
        } else {
            TXREG = fila[sai];         /* escrever em TXREG zera TXIF */
            sai = (uint8_t)((sai + 1u) % FILA);
        }
    }
    if (PIE1bits.RCIE && PIR1bits.RCIF) {
        if (RCSTAbits.OERR) {          /* estouro: a recepção PAROU */
            RCSTAbits.CREN = 0;
            RCSTAbits.CREN = 1;
        }
        char c = RCREG;                /* ler RCREG zera RCIF */
        if (linha_pronta) {
            /* o main ainda não leu a anterior: descarta */
        } else if (c == '\n' || c == '\r') {
            if (n > 0u) {              /* ignora o \n de um \r\n */
                linha[n] = '\0';
                linha_pronta = 1;
                n = 0;
            }
        } else if (n < sizeof(linha) - 1u) {
            linha[n++] = c;
        }
    }
}

/* em main(): */
uart_iniciar();
INTCONbits.PEIE = 1;
INTCONbits.GIE  = 1;
printf("Ola, serial!\r\n");
while (1) {
    /* ... */
    if (linha_pronta) {
        printf("recebido: %s\r\n", (const char *)linha);
        linha_pronta = 0;              /* só agora a ISR pode reusar o buffer */
    }
}

Programa inteiro em code/uart/main.c. Simulado a 9600 bit/s: um byte a cada 4170 ciclos (1,0425 ms), a taxa de 9592 bit/s da conta. Com printf, o programa ocupa 1,3 kB de Flash (4 % do chip).
