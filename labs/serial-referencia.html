Comunicação serial — EUSART (PIC18F4550) — Folha de Referência

Taxa, quadro, divisor e os dois erros que param a recepção

Microcontroladores — DENE/UFMTConsulta permitida

A ideia: um fio, um combinado de tempo

Na comunicação serial assíncrona não há fio de relógio. Transmissor e receptor combinam a taxa (bits por segundo) e o formato, e o receptor se sincroniza a cada quadro pela borda de descida do bit de partida.

Formato do curso, 8N1: 8 bits de dado, sem paridade, 1 bit de parada. O quadro tem 10 bits:

repousopartidab0b1b2b3b4b5b6b7paradarepouso
10dado, bit menos significativo primeiro11

largura de um bit = 1 / taxa
tempo de um byte = 10 / taxa     (9600 bit/s → 104,2 µs por bit, 1,042 ms por byte)
vazão útil = taxa / 10 bytes por segundo

Regra de ouro Os dois lados precisam do mesmo relógio, dentro de ~2 %. O receptor amostra cada bit no meio; o erro acumula ao longo do quadro, e no décimo bit a amostra já caiu no bit vizinho. Taxa diferente não dá "nada": dá caracteres errados.

Na linha TTL do pino, repouso é nível alto (5 V). No conector DB9, depois do conversor RS-232 do kit, os níveis são invertidos e maiores (cerca de ±10 V). Meça no pino, não no conector.

Gerador de taxa

O divisor n é um registrador de 8 bits (SPBRG) ou de 16 bits (SPBRGH:SPBRG, com BRG16 = 1).

BRG16BRGHTaxaDivisorFaixa de n
00FOSC / (64 · (n + 1))n = FOSC / (64 · taxa) − 10 … 255
01FOSC / (16 · (n + 1))n = FOSC / (16 · taxa) − 10 … 255
10FOSC / (16 · (n + 1))n = FOSC / (16 · taxa) − 10 … 65 535
11FOSC / (4 · (n + 1))n = FOSC / (4 · taxa) − 10 … 65 535

Procedimento: calcule n, arredonde para o inteiro mais próximo, recalcule a taxa real com o n inteiro e o erro relativo. Exemplo, 19 200 bit/s com BRG16 = 1 e BRGH = 1:

n = 16 000 000 / (4 · 19 200) − 1 = 207,33 → 207
taxa real = 16 000 000 / (4 · 208) = 19 230,8 bit/s     erro = +0,16 %

O cálculo usa FOSC = 16 MHz. Usar 48 MHz (o relógio do USB) dá um n três vezes maior, e a taxa real sai um terço da pretendida.

Erros de recepção

A recepção tem uma fila de 2 bytes, mais o registrador de deslocamento que monta o byte que está chegando.

ErroCausaConsequênciaComo sair
OERR (estouro)terceiro byte termina de chegar com a fila cheiao byte se perde e a recepção para: nenhum byte novo entra até o programa agirzerar e religar CREN
FERR (quadro)bit de parada lido como 0: taxa errada, ruído ou linha em curtoo byte provavelmente está erradoler RCREG (o bit acompanha o byte)

tempo até o estouro, a partir da fila vazia ≈ 3 bytes · 10 / taxa

Se a recepção for por consulta, todo trecho do laço principal mais longo que esse tempo pode perder bytes. A recepção por interrupção resolve: o tratamento esvazia a fila a cada byte.

Código recomendado

Inicialização

TRISCbits.TRISC6 = 0;           // TX
TRISCbits.TRISC7 = 1;           // RX
BAUDCONbits.BRG16 = 1;
TXSTAbits.BRGH    = 1;
SPBRGH = (uint8_t)(N >> 8);     // N calculado pela tabela, arredondado
SPBRG  = (uint8_t)(N & 0xFF);
TXSTAbits.SYNC = 0;             // assíncrono
RCSTAbits.SPEN = 1;             // liga a porta: RC6 e RC7 passam ao módulo
TXSTAbits.TXEN = 1;
RCSTAbits.CREN = 1;
PIE1bits.RCIE = 1;              // recepção por interrupção
INTCONbits.PEIE = 1; INTCONbits.GIE = 1;

Transmissão por consulta (bloqueante) e recepção por interrupção

void uart_byte(uint8_t b)
{
    while (!PIR1bits.TXIF) { }  // espera TXREG livre: ~1 ms por byte a 9600
    TXREG = b;
}

/* no tratamento: */
if (PIR1bits.RCIF) {
    if (RCSTAbits.OERR) {       // estouro: a recepção PAROU
        RCSTAbits.CREN = 0;
        RCSTAbits.CREN = 1;
    }
    char c = RCREG;             // ler RCREG apaga RCIF
    /* guardar c num buffer; o laço processa a linha */
}

A transmissão bloqueante prende o processador ~1 ms por caractere a 9600 bit/s: uma linha de 30 caracteres custa 31 ms. Com fila em RAM e TXIE, o laço só deposita os bytes, e o tratamento os envia (R10).

No kit: CH4-6 (RS232_TX) e CH4-8 (RS232_RX) em ON, CH4-5 e CH4-7 (RS-485) em OFF, e os relés (CH5) em OFF, porque estão ligados a RC6 e RC7. Cabo DB9 de extensão (CN4), não null-modem.
